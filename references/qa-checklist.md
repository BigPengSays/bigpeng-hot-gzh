# QA Checklist

输出前逐条过。不通过就改，不要先发给用户再补。

## 必过项

- 路径判断正确：有明确选题只走 A；无选题 / 关键词 / 空输入走 B。没有两边都做。
- 路径 A：6 条标题分属不同公式（允许少 1 条情绪型，不允许 6 条清单体）。
- 路径 B：默认 4 个方向，模板不重复；每个方向 3 个标题公式不重复。
- 主标题多数落在 18–32 字；工具名尽量出现在前 16 字。
- 数字具体。没有公开数据的社会证明公式未使用。
- 每条标题都写了「正文必须兑现什么」。
- 首选满足：截断后仍成立 + 有数字或身份 + 能兑现。情绪短句默认不当首选。
- 换赛道时只用公式，没有把 Codex / WorkBuddy / Skill 硬套进无关选题。
- 空输入时用了当前热点，没有只从语料抄过时产品名。

## 失败信号

出现以下情况，重写对应条目：

- `XX 发布了` / `盘点 XX` / `关于 XX 的思考`
- 震惊、重磅、炸裂、必看（用户没要求时）
- 「多个」「一系列」「干货满满」
- 6 条只改了两个字
- 标题写了附教程 / 提示词 / 开源仓库，兑现点却是空的
- 编造 Star、下载量、实验样本、对比分数
- 输出 JSON（本 skill 用 Markdown）
- 开始写正文（本 skill 只做选题和标题）

## 字数怎么计

按可见字符：汉字、标点、数字、字母都算。空格不算。英文产品名按实际字母数计，不按「一个词算 1」。
